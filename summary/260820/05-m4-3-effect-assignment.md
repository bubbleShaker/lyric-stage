# M4-3: 本編シートへの演出割り当て

Issue [#16](https://github.com/bubbleShaker/lyric-stage/issues/16)

## 何をしたか

演出プリセットが 8 つ揃ったので、本編 `public/lyrics/shining-star.json` の全 51 行に
`effect` を割り当てた。**コードは 1 行も足していない**（レジストリ方式にした狙いがそのまま出た）。
足したのは割り当ての方針を守る検査 3 つだけ。

## 割り当ての方針: 対応する行は同じ演出

1 番・2 番・ラスサビの**同じ歌詞には同じ演出**を当てた。毎回変える案もあったが、
それだと画は賑やかになる代わりに曲の構成が散る。繰り返しを「型」にすると、

- `シャイニングスター綴れば` が迫ってくる → サビ頭
- `I'll believe of my sensation` が乱れる → サビの折り返し

と、**音を聞かなくても画だけで構成が分かる**。

| 区間 | 演出 | 選んだ理由 |
|---|---|---|
| A メロ前半 | `fade` | 漂う情景（ただ風に揺られて／ただ雲を眺めて） |
| A メロ後半 | `typewriter` | 自分に言い聞かせる語り（誰しも何かしら／ただそれだけのこと）。サビ内の `魔法が使えるような` にも当てている（呪文を唱える感じ） |
| 決意・余韻の行 | `bounce` | 悩むのはもうやめた／大空を翔る／トキメキを感じて／熱いメロディになる／LaLaLa |
| 伸ばしの行（6 秒前後） | `vertical` | 場面転換 |
| サビ頭 | `zoomLine` | 行全体が手前から迫る。サビの合図 |
| 降り注ぐ／イマジネーション | `shatter` | 破片が集まって行になる |
| 短い決めの行 | `zoom` | 新たな世界へ／一滴の光／世界が広がる／心の真ん中で |
| Latin の行 | `glitch` | 英字と機械的なノイズ |

「対応する行は同じ演出」は**同じ歌詞**についての方針で、位置についての方針ではない。
1 番と 2 番のサビ前は構造的には同じ位置だが、`時を閉じ込めて` は `typewriter`（1 文字ずつ
閉じ込める）、`大空を翔る` は `bounce`（上昇）と分けている。歌詞が違う行では歌詞の意味を優先する。

## 決めたこと

### Latin の行は縦書きにしない（M4-2 の未決の決着）

`writing-mode: vertical-rl` は `text-orientation` を指定しないとラテン文字を横倒しにする。
これは**日本語縦組みの慣例どおりの正しい挙動**なので、CSS で場合分けして戦うより
縦書きを日本語の行にだけ当てる方が素直。`text-orientation` は足していない。

### `vertical` は伸ばしの行にだけ当てる

`さざなみの音に癒やされてく` / `月の光 隠す雲は揺らぎ` / `切なさやトキメキが輝き出す` の 3 行。
いずれも間奏やサビ前の余白にあたる。縦組みは画が大きく変わるぶん場面転換として効くが、
行が 3 秒ごとに入れ替わる区間で使うと**組み方が毎行変わって落ち着かない**。

### 本編シートは全行に `effect` を明示する

省略すると既定の `fade` で動いてしまうので、「意図して fade を選んだ行」と
「割り当てを忘れた行」が**画面を見ても区別できない**。テストで書き忘れを落とす。
`sample.json` は既定値の挙動を見せる役なので対象外。

## 足した検査（`src/lyric-sheets.test.ts`）

方針は文章で書いても破られるので、全て実行できる形にした。

| 検査 | 守るもの |
|---|---|
| 全ての行に演出が書かれている | 割り当ての書き忘れ |
| 同じ歌詞の行には同じ演出が当たっている | 「対応する行は同じ演出」の方針 |
| 縦書きの行にラテン文字が含まれていない | Latin を横倒しにしない |
| 縦書きは行が長く留まる所にだけ当たっている | 「`vertical` は伸ばしの行に」の方針 |
| 各行の演出がその行の猶予に収まる | 実際の組み合わせで演出が間に合うこと |
| 最後の行が消える時刻を持っている | 最終行の出しっぱなし |

縦書きの 2 つは `resolveEffect(line.effect).layout === 'vertical'` で判定している。
演出名を直接見ていないので、**将来 `vertical` 系の演出が増えても検査は追従する**。

## レビューで直したこと

- **最後の行に `duration` が無く、アウトロの約 41 秒を出しっぱなしにしていた。**
  既存の「次の行が来る前に出揃う」検査は最終行の猶予を `Infinity` として扱うので、
  ここだけ構造的に測られていなかった。`duration: 6.0` を置き、検査も足した
- **「`vertical` は伸ばしの行に当てる」だけが検査で守られていなかった。** 4 つの方針のうち
  最も静かに壊れるもの（M6 で `time` を詰めると縦書きの行が短い区間に紛れ込む）だったので追加
- **既存の「どの演出も次の行が来る前に出揃う」は、割り当てが確定した今は必要以上に硬い。**
  「28 文字の行 × 2.25 秒の猶予」という実在しない組み合わせで全演出を測っている。
  実際の組み合わせを測る検査を別に足し、こちらは「まだ割り当てていない演出も含めた安全網」
  として役割を書き分けた（伸ばしの行専用のゆっくりした演出を足すときは、こちらを緩める）
- ラテン文字の判定を `/[A-Za-z]/` から `/[\p{Script=Latin}\p{Nd}]/u` へ。全角英字・
  アクセント付きの文字・数字も同じように横倒しになる

## 確認したこと

- `npm test`（65 件、M4-2 から +6）/ `npm run build`（`tsc` 込み）
- 実際の画面を 8 か所で撮って確認（`vite preview` + Chromium、シークバー経由で再生位置を送る）
  - 縦書き 3 行はいずれも 2 段に収まり、再生コントロールに重ならない
  - 812×375（横持ちスマホ相当）でも 3 段で読める
  - 縦書きの前後の行が横書きに戻っている（`className` が `stage__text` に戻る）
  - `glitch` の RGB ずれ、`shatter` の飛散、`zoomLine` の着地を目視

`<audio>` は `new Audio()` で作られて DOM に無いので、自動確認では
`#transport-seek` に値を入れて `change` を飛ばす経路で再生位置を動かした。
