# M3: 演出プリセット第一弾（fade / typewriter / bounce）

2026-08-20 / Issue #10

## やったこと

`src/stage/effects.ts` のレジストリに登場演出を 3 つ揃えた。歌詞シートの `effect` に
名前を書くと、その行だけ演出が変わる。

| 演出名 | 見え方 | 実装 |
|---|---|---|
| `fade`（既定） | 下からふわりと出る | `yPercent: 40` + `power3.out` |
| `typewriter` | 1 文字ずつ打ち込まれる | ほぼ瞬時（`duration: 0.01`）に出す文字を等間隔に並べる。`ease: 'none'` |
| `bounce` | 1 文字ずつ跳ねて出る | `back.out(2.6)` で目標値を追い越して戻す。足元を軸に潰れて伸びるよう `transformOrigin: '50% 100%'` |

表示側（`LyricStage`）は一切触っていない。M2 で `switch` を書かずレジストリにしたので、
**演出の追加はこの表にエントリを 1 つ足すだけ**で済んだ。

## 文字送りの上限（この回でいちばん考えたところ）

1 文字ごとの遅延（GSAP の `stagger`）を固定値にすると、文字数の多い行で最後の文字が出る前に
次の行へ切り替わる。本編の実測は **行間隔が最短 2.25 秒・最長の行が 28 文字**なので、
`typewriter` の 0.08 秒を固定で使うと 28 文字＝約 2.2 秒かかり、ほぼ間に合わない。

そこで `staggerFor(文字数, 希望の間隔)` を挟み、**文字送りの合計が 0.8 秒を超えないよう頭打ち**にした。

```
staggerFor(count, preferred) = min(preferred, 0.8 / (count - 1))
```

短い行では希望どおりの間隔（＝その演出らしいリズム）が出て、長い行だけ自動的に詰まる。
「文字数に依らず、行が変わる前に必ず出揃う」ことが保証される。

## テスト

gsap は DOM が無くても、ただのオブジェクトをトゥイーンできる。そのため文字要素の代わりに
ダミーを渡せば、**ブラウザ無しでタイムラインの長さを検証できる**（vitest の実行環境は node のまま）。
ただしダミーには CSS プラグインが働かないので、**検証できるのは時間の組み立てだけ**。
`yPercent` の綴りを間違えても緑になる。見た目そのものは目で見て確かめるしかない。

`src/stage/effects.test.ts`（演出単体の性質）:

- `staggerFor` の頭打ちと境界（0 文字・1 文字）
- どの演出も文字数が増えると総時間が伸びないこと（＝上限が効いていること）
- `resolveEffect` のフォールバック（未知の名前、および `__proto__` / `toString` のような
  `Object.prototype` 由来の名前を演出として拾わないこと）

`src/lyric-sheets.test.ts`（実データとの突き合わせ）:

- 本編シートに**知らない演出名が書かれていない**こと。未知の名前は既定の演出に落ちて
  動いてしまうので、綴りの間違いは画面を見ても気付けない
- **どの演出も次の行が来る前に出揃う**こと。所要時間は文字数で、猶予は行間隔で決まり、
  どちらも実データ側で変わる（M6 で time を詰めたときなど）ので、定数を書かずにシートから測る

演出名の型付けは `satisfies Record<string, Effect>` にした。型注釈だと `Record<string, Effect>` に
広がり、既定の演出名（`DEFAULT_EFFECT`）を打ち間違えても型検査を通ってしまうため。
今は `EffectName = keyof typeof effects` が効き、存在しない名前を既定にすると `tsc` が落ちる。

## 動作確認

音源を読み込む本編ページは、この WSL の headless Chromium だと mp3 のレスポンスが返らず
（サーバ側は 5.5MB を 63ms で返せているので環境側の問題）自動確認ができなかった。
そこで **`effect-preview.html`（開発用）** を足し、音源と歌詞タイミングに縛られずに
演出だけを表示できるようにした。Vite のビルド入口は `index.html` だけなので、
このページは `dist` に入らない＝公開サイトには出ない。

確認できたこと:

- 3 種とも意図した見え方になっている（`bounce` は文字が階段状に上がってくる）
- 演出後は全文字が `opacity: 1` / 変形なしの素の状態に戻る（やり残しの transform が無い）
- 行を 30 回差し替えても `#stage-text` の要素数が増えない（`SplitText.revert()` が効いている）
- コンソールエラー無し

## やらなかったこと

- **退場演出**。行の切り替えは今のとおり即座に消える。入れると `clear()` が非同期になり、
  「消し終わる前に次の行が来た」の面倒を `LyricStage` が抱える。演出が出揃ってから考える
- **本編 `shining-star.json` への割り当て**。M4 の「刻む」系が出揃う前に振ると、やり直しになる
- **`Effect` 型の拡張**（行全体・単語単位）。M4 で必要になってから広げる
