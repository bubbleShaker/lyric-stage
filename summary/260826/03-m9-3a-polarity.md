# M9-3a — 明暗の反転の仕組み（シートに書いた極性で画そのものが裏返る）

2026-08-26 / [Issue #57](https://github.com/bubbleShaker/lyric-stage/issues/57)

## 何をしたか

M9 の三段目。M9-1 が配色を静的に反転し（暗い地 → 退色した紙）、M9-2 が文字を地に刷り重ねた。
ここでは **反転を曲の途中で起こす**（参考にした米津玄師「IRIS OUT」MV の核）。

歌詞シートの行に `polarity: 'paper' | 'ink'` を書くと、その行から先の画がまるごと裏返る。

M9-3 はもともと「インクのにじみ（SVG フィルタ）か、拍での明暗の反転か」の二択で保留していた。
にじみを採らなかったのは 2 つの理由:

- **`filter` は当てた要素の 3D レンダリングコンテキストを flat に畳む。** 当て先になるのは
  `.stage__lines` だが、あそこは M8-5 の `perspective` の本体。`rushIn` の `z: -1400` や
  `swing` の奥行きが「ただの平行移動」に化ける。`.stage__frame` へ逃がす道は M8-1 の実測
  （GSAP と transform を取り合う）で塞がっている
- **役割が重複する。** 「紙の質感」は `GrainField` の粒が既に担当していて、にじみは
  同じ方向に足す手になる

## 一番大きな判断 — 段を入れ替えるのではなく、最後に画を裏返す

M9-1 で分かったのは、**地の明暗に依存していたのは色の指定ではなく「色に対する操作」**
だということ。5 か所あった（ビネットの向き・粒の濃さ・拍の膜の係数 0.035・ガラスの透過・
`color-scheme`）。

`--stage-bg` と `--stage-ink` を入れ替える方式だと、**この 5 か所すべてを両極で成立させる**
ことになり、値が 2 組になる。それは M9-1 が「`PALETTE` は 1 組しか持てない」
「作品は 1 つの見えに決める」と書いて避けた道そのもの。

そこで **`filter: invert(1)` を画の一番外側に当てる**。パレットは 1 組のまま、
M9-1 が名指しした「操作」の側に一本化する。5 か所は勝手に辻褄が合う
（ビネットは影から光へ、透過は黒から白へ）。

```
body
 └ .scene            ← isolation: isolate ＋ 極性が ink の間だけ filter: invert(1)
    ├ canvas.backdrop   (z-index: -2)
    ├ .screen-decor     (z-index: -1)
    ├ main.stage
    │   └ .stage__lines   ← perspective（M8-5）と mix-blend-mode: multiply（M9-2）
    ├ .transport
    └ footer.credit
```

## 決めた分岐点

### 当て先に専用の枠が要る（`body` では効かない）

**`html` が背景を持たないと `body` の背景は root へ伝播し、`body` 自身のものではなくなる。**
`body` に `filter` を当てても地の色だけが元のまま残る — 例外も検査の赤も出ない壊れ方。
地の色ごと `.scene` へ引っ越した。

### `isolation: isolate` は極性に関わらず常に要る

反転していない間は `filter: none` になる。そのとき枠がスタッキング文脈を作らないと、
**負の z-index の子（背景 -2・画面の図形 -1）が枠の外へ抜けて枠の背景の下に沈む**
＝ 背景と分割線が両方消える。

headless Chrome で実測して確かめた。3 枚並べて撮ると、`isolation` を外した B だけが
背景と図形を失って乗算の層しか残らない:

| | A: isolation あり | B: isolation なし | C: isolation + invert(1) |
|---|---|---|---|
| 結果 | 正常 | **背景と図形が沈む** | A がそのまま裏返る |

**ink の画を見ている限りこの壊れ方には気付けない**（`filter` 自身が文脈を作るため）。
paper に戻した時だけ壊れる。

### 再生コントロールとクレジットも枠の中（＝一緒に裏返る）

外に出すと、M9-1 が名指しした 2 か所 —— `.credit` の「不透明度による減光は地の明暗に対して
非対称」、`.transport` のガラスの「透過は明暗が逆でないと厚みとして読めない」——
がそのまま動的に再発する。一緒に裏返せばコントラスト比は保たれる:

| | paper | ink |
|---|---|---|
| 地に対する `ink` | 16.58 | 16.51 |
| 地に対する `sub` | 5.12 | **6.82** |
| 帯の上の `ink` | 12.77 | 12.18 |
| ビネットの縁の `sub` | 4.79 | 6.06 |

**代わりに差し色の色相が裏返る**（朱 `#c62f1c` → シアン）。M8-2 で「差し色は 1 色」と
決めた線に対する例外だが、読めなくなるより良いと判断した。「触れる所だけが有彩色」という
役割の方は裏返っても保たれている。

### 極性は行の属性ではなく「状態」

`effect` / `place` / `decor` / `sub` と決定的に違う点。書いた行から先ずっと続く。
行の属性（＝その行だけ反転）にすると次の行で必ず戻り、**行間隔 2.25 秒の明滅**になる。

読む側は変化点だけを抜いた `PolarityTrack` を一度組み立て、毎フレーム二分探索する
（`BeatPulse` を一度作って `pulseAt` で読むのと同じ形）。行の列を毎フレーム遡ると、
極性を書いていない行が続くほど探索が伸びる。

### 状態は行より前から在りうるので、行とは別に持つ場所が要る

区間で切り出すと、区間の外で立てた極性は行ごと落ちる。当初は「生き残った最初の行へ移す」
形にしたが、**区間の頭には行が無い** — `WORK_WINDOW` は助走を 1 小節ぶん取ってあり、
本編の最初の行は 3.01 秒。**助走のあいだだけ既定の極性で始まり、歌い出しで画が裏返る**
という、同じ壊れ方が規模を小さくして残っていた（レビュー指摘 🔴）。

`LyricSheet.polarity` / `PolarityTrack.initial` を足して、そちらへ畳む。

副産物として、**切り出しが切り替えの間隔を縮める経路が消えた**。区間の頭を跨ぐ行は
時刻 0 へ詰められるので、極性を行に載せていた頃は「元は 1.1 秒差 → 切り出すと 0.6 秒差」に
なりえた。今はその行の極性が `initial` に畳まれて変化点にならない。区間の中の行どうしは
一様に同じ秒数だけ動き、頭を跨ぐ行はどの並びでも高々 1 つ — この 2 つで縮む経路が尽きている。

### 明滅の安全は「壁を置ける場所が入口しかない」

全画面の反転は相対輝度の変化が桁違いで、WCAG 2.3.1 の general flash threshold を軽く超える。
**拍ごと（2.66Hz）には絶対にできない。** 閾値が適用されるのは「1 秒に 3 回以上」なので、
切り替えの最短間隔に 1 秒（最大 1Hz）の下限を掛ける。

**`domain/beat.ts` とは守り方が違う。** あちらは `createFlashPulse` が下限を下回る値を
返さない ＝ **細かく刻めない形**にしてあるが、極性はデータで書くものなので同じ手が使えない。
`parseLyricSheet` が入口で落とす。数えるのは**実際に極性が変わった回だけ**
（同じ極性を続けて書いても画は変わらないので、数えると安全の検査だけが落ちる）。

拍の膜（係数 0.035）は両極とも閾値の外（実測: paper で変化 0.063 / 暗い方 0.810、
ink で 0.004〜0.007）。sRGB の段としては両極とも同じ 5/255 の振れなので、画としては
暗い側でもちゃんと瞬く — **係数を極性ごとに持つ必要は無い**（持てば値が 2 組になる）。

### `prefers-reduced-motion` では畳まない

反転は動きではなく明暗の切り替えなので前庭系の話に乗らず、発作の側は上の下限が構造で守る。
M9-1 で粒とビネットを消さなかったのと同じく、反転は構図の一部。

## 検査で守っているもの

画を見ても分からない、あるいは「何も起きない」形で出る間違いだけを機械に見張らせる。

- 極性の属性を当てにした CSS の規則が実在する（読み忘れると、値は正しく書かれているのに画が静止）
- 素の `.scene` に `filter` を書かない（極性に関わらず常に裏返る）
- `isolation` と `position: fixed; inset: 0` が残っている
- 地の色は `.scene` が持ち、`body` は持たない（伝播の罠）
- 背景・ステージ・再生コントロール・クレジットが枠の中に居る
- 極性の初期値を HTML に焼き込まない（歌詞が読めなかった時にその値のまま貼り付く）
- 切り出した後のシートでも切り替えの間隔が縮んでいない

## つまずいたところ

- **CSS の走査はコメントを先に落とす**（M8-2 が `palette.test.ts` で書き残した罠を踏み直した）。
  `.scene` の説明が `body` と `.stage__lines` を名指ししているせいで、**選択子の手前の
  `[^{}]*` がコメントを飲み込み、`.scene` の規則が「body の規則」「`.stage__lines` の規則」
  として拾われていた**。後者（`blend.test.ts` が M9-2 の当て先を見張る検査）はレビューで
  指摘されるまで気付かなかった — `some(...) === true` の主張なので緑のまま素通りしていた。
  これを機に `rulesFor` を `src/test-support/css-rules.ts` へ括り出した（M9-2 で決めた
  引き金「1 か所直すのに複数を触ることになった時」がここで引かれた）
- **HTML の入れ子を数える検査は `lastIndexOf('</div>')` では書けない。** 枠の外へ出した要素が
  `div` だと、その要素自身の閉じタグが終端になって**外に出したものが中に入って見える**。
  `.transport` を外へ移す変異が実際に素通りしていた（`canvas` / `main` / `footer` が
  捕まっていたのは div ではないという偶然）
- **`WindowedPlayback.currentTime` は負を返さない**（`Math.max(0, …)` で下げ止まる）。
  助走の 1 小節は区間の**内側**。同じ思い込みが `domain/beat.ts` と `stage/grain-field.ts` の
  コメントにも残っている
- **この WSL でも headless Chrome の `--screenshot` は動く**（Windows 側の `chrome.exe` を
  使う場合）。M8-3a が「固まるので `getBoundingClientRect` で代用した」と書いたのは Linux 側の
  headless の話。`--screenshot=C:\...` と URL の両方を**絶対の Windows パスで**渡すこと
  （相対だと Windows 側の cwd に書かれて見失う）
